# Research Synthesis Skill

## Trigger
Use when you have raw research data — interview transcripts, survey results, usability test notes, support tickets, NPS responses — and need to distill it into themes, user segments, insights, and prioritized recommendations.

## Goal
Transform messy, qualitative or quantitative research data into clear patterns, actionable insights, and evidence-backed recommendations that teams can act on.

## Process

### 1. Intake & Inventory
Before synthesizing:
- How many participants / responses?
- What research method(s)? (interviews, surveys, usability tests, support tickets, analytics)
- What was the core research question?
- What decisions does this research need to inform?

### 2. Data Preparation
- Read all raw data before identifying patterns
- Note direct quotes that are particularly vivid or representative
- Flag anything surprising, contradictory, or emotionally charged

### 3. Affinity Clustering
Group observations into clusters:
1. Extract atomic observations (one idea per note)
2. Group similar observations — don't force fit
3. Name each cluster with a neutral label first, then an insight label
4. Count frequency: how many participants mentioned each theme?

### 4. Theme Identification

For each theme:
```
Theme: [Name]
Frequency: [X of Y participants / % of survey responses]
Summary: [1-2 sentence description of the pattern]
Evidence:
  - "[direct quote]" — Participant 3
  - "[direct quote]" — Participant 7
  - [paraphrased observation from usability test]
Implication: [what this means for the product/design]
```

### 5. User Segments
If the data reveals meaningfully different types of users:
```
Segment: [Name]
Size: [% or count if known]
Defining Characteristic: [what sets them apart]
Key Need: [what they most want]
Key Pain: [what frustrates them most]
Representative Quote: "[quote]"
```

### 6. Insight Statements
Insights go beyond observations — they explain the "why":

Formula: `[User type] needs [goal] because [underlying motivation], but [barrier].`

Example: *"New users need to understand pricing immediately because they're comparing multiple tools, but the pricing page is buried in the footer."*

### 7. Prioritization Matrix
Rate each insight on:
- **User Impact** — how many users affected, how severely (1–5)
- **Business Impact** — revenue, retention, acquisition effect (1–5)
- **Confidence** — how well-evidenced is this? (1–5)

Priority Score = (User Impact + Business Impact) × Confidence

### 8. Recommendations
For each top insight, provide:
```
Insight: [one sentence]
Recommendation: [specific, actionable suggestion]
Effort: [Low / Medium / High]
Impact: [Low / Medium / High]
Evidence Strength: [Weak / Moderate / Strong]
Next Step: [concrete first action]
```

## Output Structure
1. **Research Overview** — method, sample size, key question, date range
2. **Key Findings** — top 5 themes with frequency and evidence
3. **User Segments** — distinct groups identified (if applicable)
4. **Insight Statements** — "needs / because / but" format
5. **Prioritized Recommendations** — sorted by priority score
6. **Gaps & Next Steps** — what this research didn't answer; suggested follow-up
7. **Appendix** — full theme inventory, raw quote bank
